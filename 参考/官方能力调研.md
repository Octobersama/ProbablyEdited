# ProbablyEdited 官方能力调研

**结论（查询日期：2026-11-11）**：官方指南提供自建 UI 和受限数据存储；进入实现阶段并获得用户授权后，本机程序集元数据进一步确认了 Unity 全表枚举、`LoadedMod.Localization` 公开字典和 `ModConfigWindow.Open(LoadedMod)` 设置入口。实现使用两条文本来源及只针对本模组的设置入口补丁。用户已确认覆盖范围为本体字符串表和已启用模组的官方本地化字典；硬编码、自建文本系统与动态拼接内容明确排除。元数据签名及逻辑测试不能代替游戏内完整验收。

本次重新核对官方仓库 `APIChanges.md` raw 主分支：最新条目仍为 2026-11-08；本次按 2026-11-11 记查询日期，不把未发布的新条目推断为存在。Context7 未找到 Probably Stolen 官方 mod API 文档；Unity 通用 Localization 文档也不能代表游戏自己的语言选择器。下文分别标明官方文档与本机只读元数据证据。[^repo]

## 1. 本地化、字符串表与来源

### 官方已证实

- `ModHelper.GetCurrentLocale().Identifier.Code` 可读当前 locale code。官方列出 11 个代码：英语 `en`、法语 `fr`、德语 `de`、俄语 `ru`、中文 `zh`、日语 `ja`、西班牙语 `es`、巴西葡萄牙语 `ptBR`、韩语 `ko`、意大利语 `it`、波兰语 `pl`。[^loc]
- 模组自己的文本放在 `Localization/<localeCode>.csv`，每行是 `key,text`、UTF-8、无表头；允许双引号和 `\n`。`ModHelper.GetLocalized(modId, key, args...)` 按当前 locale、`en`、原 key 的顺序回退。模组条目仅支持编号格式参数 `{0}`、`{1}`；本体内置 string tables 可用的 Smart Strings（命名占位符、复数规则、`choose()`）**不适用于模组条目**。文件在 `Init`/`OnEnable` 后加载；`ModHook.OnModAssetsLoaded(LoadedMod)` 对每个启用模组触发。[^loc]
- 官方调试命令 `loc-plural-test <table> <key>` 与 `loc-smart-list` 能测试条目/列出使用复数格式的条目；文档没有说这些命令是通用字符串表枚举 API。[^dev]
- API Changes 记录了 `ModLoader.Mods`（当前返回副本）及 `IsModEnabled`；官方指南也说明 `OnModAssetsLoaded` 的 `LoadedMod` 参数可识别模组，且日志能显示该模组加载的 locale 和 localization entry 数。[^changes][^assets]

### 本机只读证据（父任务调查）

`Probably Stolen_Data/StreamingAssets/aa/settings.json` 显示 `m_AddressablesVersion=1.19.19`、`m_buildTarget=StandaloneWindows64`。同目录 `catalog.json` 的 `m_InternalIds` 可见 14 组 Shared Data：`ClientName`、`Dialogue`、`PhoneDialogue`、`Interactable`、`Hint`、`Item`、`MainMenu`、`Mechanic`、`NetworkUpgrade`、`NewGame`、`PerkTable`、`RepPerkTable`、`Tutorial`、`UI`；每组可见 11 个语言资源路径。静态目录不是枚举全集，实际代码动态读取数据库与启用模组字典。

### 已选路线与剩余边界

- 可先保留原始表名，再提供建议分组：人物/对话（`ClientName`、`Dialogue`、`PhoneDialogue`）、物品/交互/提示（`Item`、`Interactable`、`Hint`）、界面/主菜单（`UI`、`MainMenu`）、机制/新游戏与成长（`Mechanic`、`NewGame`、`NetworkUpgrade`、`PerkTable`、`RepPerkTable`）、教程（`Tutorial`）。这是按表名形成的**分类建议**，不是官方给出的语义分类；实机核对内容后再改类，且动态发现的模组表必须纳入，不能把 14 组硬编码为全集。
- 本机 `Assembly-CSharp.dll` 元数据确认：`ModLoader.Mods` 是公开静态 `List<LoadedMod>`；`LoadedMod.Localization` 是公开 `Dictionary<string, Dictionary<string,string>>`，第一层为语言、第二层为文本键。`ModHelper.GetLocalized` 的静态方法引用也确认它读取所选 locale 的确切 code，再回退 `en`，因此代码保留语言标识的大小写/连字符，不擅自把 `pt-BR` 改写成 `ptBR`。不同模组的 CSV 键各有模组 ID 命名空间，不假定它们全局互相覆盖。
- 本机 `Unity.Localization.dll` 元数据确认 `StringDatabase.GetAllTables(Locale)`、`StringTable.SharedData.Entries`、`StringTableEntry.Value/IsSmart` 和 `LocalizeStringEvent.RefreshString()`。Unity 的版本化官方文档继续保留作更新参考；本机程序集版本号为 `0.0.0.0`，不能据此确定 Unity package 版本，Addressables 的 `1.19.19` 也不是它的版本。[^unity-tables]
- 对应实现见 [`GameTextCatalog.cs`](../src/GameTextCatalog.cs)：保留原表名、未知表继续枚举；单独记录本语言缺失键和英语参考，不把自己的既有覆盖当作原文。注册进数据库的第三方表未必提供作者信息，界面如实标记数据库来源；硬编码/自建系统不可通用枚举，用户已接受此边界。

### 实机暴露的生命周期约束

- `ModHelper.StartCoroutine` 在模组尚未注册为运行状态时返回空；不能直接从 `IMod.OnEnable` 启动本编辑器的初始化。当前在自己的 `ModHook.OnModAssetsLoaded` 回调后启动，实机已从持续“读取中”恢复为正常目录加载。
- 本机 `GetAllTables` 在完成后的下一帧自动释放操作。保存 `Result` 引用却不持有句柄会导致切换到非当前语言时缓存表列表被清空。当前在等待前调用 `Addressables.ResourceManager.Acquire(request)`，退出时逐个释放；依据为本机方法体和 [Addressables 引用计数 API](https://docs.unity3d.com/Packages/com.unity.addressables@1.19/api/UnityEngine.ResourceManagement.ResourceManager.html)（查询日期 2026-11-09）。

## 2. 原生模组设置 UI 与动态编辑器

- `ModHelper.GetConfig(modId).Define(...)` 注册类型化设置并使本模组齿轮可用。它没有文档化的动作按钮接口；本机元数据确认公开静态 `CustomUIWindow ModConfigWindow.Open(LoadedMod)` 后，采用 Harmony Prefix，仅当 ID 为 `probably_edited` 时返回编辑器窗口，其他模组完全走原方法。此入口是需随版本维护的补丁，不是虚构的官方自定义设置页 API。对应 [`ModEntry.cs`](../src/ModEntry.cs)。[^config][^gameopt]
- 官方支持单独的 `CustomUIManager.Window(...)` 窗口；有 `AddLabel`、`AddInput`、`AddButton`、`AddDropdown`、`BeginTabs`、`BeginScroll`/`BeginScrollFlexible`。`AddInput` 的 `onTyping` 可逐键响应；指南给出过滤列表时保留窗口焦点的动态重建做法：清理 `CurrentContainer` 后用 `CustomUIBuilder` 重填。`WithTooltip(text)` 给最后一个控件附悬停提示。由此可用自建窗实现文本行、搜索过滤、分页按钮和悬停说明；这些是组合现有控件的实现，不是内置字符串表编辑器。[^ui]
- 文档未记载虚拟化/分页专用控件、超大列表性能上限或通用文件选择器。分页/筛选需自行管理；大量行的滚动、焦点、输入、性能和悬停行为须实机测试。官方支持新增窗口，但明确不支持改造/替换现有内置 UI；应使用自建窗口。[^ui][^support]
官方机器窗口文档还提供 `MachineryText.WithInfoLink(id, tooltipProvider)`：在文本末尾添加原生 info 图标并以悬停 tooltip provider 提供说明。这是比自绘“?”更准确的官方能力；文档没有展开图标视觉状态或动态 provider 的具体刷新时机。`CustomUIWindow.SetSize(width,height)` 是另一套 CustomUI 窗口 API，不能据此推导原生 `optionUIPrefab` 的内框尺寸或调整目标。[^machine-ui][^ui]

本机只读 `Assembly-CSharp.dll` 元数据（父任务核对）显示，原生语言下拉由 `MainMenuUIController` 的私有静态 `LOCALE_DROPDOWN` 驱动，事件处理分别消费元组的 `Item2`（显示）和 `Item1`（locale code）；静态初始化列出 `en/zh/ru/de/ja/fr/es/pl` 八项。它不是 `LocalizationSettings.AvailableLocales`：后者本机可见 11 种 locale（还含 `ko/it/ptBR` 等），不等于 UI 实际提供的选择项。文档只公开 `ModHelper.GetCurrentLocale()` 读取当前语言，没有公开游戏 UI 语言清单；`LOCALE_DROPDOWN` 是私有且版本敏感的实现。官方 APIChanges 说明固定字面游戏类型/成员的反射按直接调用规则审查，游戏类型在许可范围内；对该固定游戏字段的只读 Harmony 读取不需要 `reflection-external`，但仍是未文档化实现而非稳定的公开 API。[^changes][^loc]

Steam Workshop 条目 3834556946 的准确标题是 **In-Game Mod Settings**，发布者是小行星；页面说明其在原生 Options 添加模组设置入口，可汇总标准 ModConfig 页面。父任务只读安装目录 manifest 给出的 ID 为 `asteroid_in_game_mod_settings`、版本 `1.0.0`，`<Prerequisites />` 为空，描述本身将其作为建议安装项。若要向用户推荐而不硬依赖，精确写法是把该 ID 放在 manifest 的 `<Prerequisites><Mod>asteroid_in_game_mod_settings</Mod></Prerequisites>` 中、不要引用其 DLL；官方明确缺失 prerequisite 只产生 warning，这种 optional-only 集成仍加载；若 DLL 真实引用该 mod，其缺失会导致依赖程序集加载错误。再在 Workshop description 说明“推荐安装”及链接，因为 Steam 不会自动订阅 prerequisite。不得把它写入强制依赖语义或让实现要求其服务。父任务核对本机 `ValidatePrerequisites` IL：未找到 enabled prerequisite 时只拼接并记录 `[ModLoader] ... requires ... which is not loaded/enabled.` warning，循环后正常返回，没有 throw 或禁用路径；这是本机该 build 的直接实现证据。[^prerequisite][^workshop-item]
- 1.1.1 按本机原版设置页复用 `CreateWindow`、`optionUIPrefab`、`Style.Auto` 和 `UseMetaPrefabs`，保留预制体内框尺寸，状态与操作分行。韩语字体来自游戏的 `ScriptFontSwap.FontForText`；只处理本模组窗口及其新生成的下拉项，不修改全局字体或重新分发字体资产。对应 [`NativeFontSupport.cs`](../src/UI/NativeFontSupport.cs)。
- 差异标记使用独立几何叠层，不写入输入字符串。TMP 滚动会移动文本 RectTransform，叠层须按实际四边形范围裁切；图形重建期间的再次重绘延至帧末，避免重入。对应 [`TextDiffHighlighter.cs`](../src/UI/TextDiffHighlighter.cs)。

## 3. 存储、覆盖文件与导入边界

- `ModHelper.SetModData*` 是**按存档运行**保存，随每次游戏存档写入；官方明确说保持很小（KB 量级可用），不应用于大量文本。[^save]
- `ModConfig` 是每模组一份可读 JSON，跨存档槽共享、适合少量有类型的设置；它不是承载动态全文覆盖表的首选。[^config]
- 对非存档型文件，官方无需声明 `files` capability 的 helper 可读写自己的 `persistentDataPath/ModData/<modId>/`：`WriteModDataFileText/Bytes`、`ReadModDataFileText/Bytes`、`ListModDataFiles`、`DeleteModDataFile`、`GetModDataFolder`。路径必须相对且留在限定目录内；绝对路径、空路径、`../` 抛 `ArgumentException`。本项目推荐**带格式版本的 UTF-8 JSON 差量文件**，只记录用户修改的条目标识、替换文本、语言和可确认的来源依赖；由接收者放入自己编辑器的专属数据目录并在游戏内选择导入，不分发整份本体原文。此格式是项目建议，不是官方预定义协议。[^files]
- `ReadModFileText/Bytes` 读取模组安装目录（相对路径、只读）；不要把用户数据写进 Workshop 模组目录，Steam 更新会覆盖它。只能写自己的 ModData 目录；其他模组的数据目录可读但不可写。[^files][^changes]
- 官方文档没有暴露从任意磁盘路径弹出文件选择器/导入 API。`GetModDataFolder` + `ListModDataFiles` 提供了“用户先用系统文件管理器复制到专属目录，再由游戏内选择导入”的可证实路径；若要求用户在游戏内从任意路径选文件，接口仍未知。直接 `System.IO` 文件读写计入 `files` capability。[^files][^caps]

## 4. 开发、版本与 API 约束

- 官方 README 要求 C#、.NET SDK 6.0+；项目示例目标 `netstandard2.1`、`LangVersion=latest`，引用游戏目录 `Probably Stolen_Data/Managed` 下的 `Assembly-CSharp.dll`、`UnityEngine.dll`、`UnityEngine.CoreModule.dll`、`0Harmony.dll`。安装时在 `Mods/<mod>/` 放根目录 `manifest.xml` 和实现 `IMod` 的 DLL；`<Assemblies>`、`<Capabilities>` 必需，资产-only 模组也仍需 DLL。README manifest 示例里的 `<GameVersions>0.46</GameVersions>` 是示例值，不是当前版本声明。[^readme][^manifest]
- 本机 Steam App ID `4348910`、build ID `26525552`。主菜单和 `PlayerStore.VERSION` 显示 `VERSION 100-Rev13`；兼容检查 `ModUIManager.VersionMatchesGame` 实际读取 **`UnityEngine.Application.version`**，加载器运行日志 `audit: game 0.46D` 确认其值。manifest 因此填写 `0.46D`，并已在原生模组列表显示绿色匹配；两种版本标识不能混用。SDK 为 `8.0.420` 和 `10.0.100`。[^readme]
- `APIChanges.md` 最新条目（2026-11-08；本次于 2026-11-11 复查，未见更新条目）要求按当前扫描器声明所用 capability。**以本次查询日 2026-11-11 为准**，`files`/`network` 需要声明、会显示给玩家并要求确认；Workshop 在 2026-12-10 更新起才会对声明其中任一项的模组要求开发者验证，日期前只有提示/`mod-scan` 的 `VERIFICATION` 线，未验证本身不阻止加载；本地 `Mods/` 不受该验证要求。`dynamic-code`、`native`、`reflection-external`、`threads` 目前仍是警告/可加载，计划自 2026-12-10 更新起拒绝。APIChanges 同时说明，对字面类型和字面成员的反射按目标成员直接调用规则计类；固定游戏 Assembly-CSharp 类型/字段不因使用反射自动构成 `reflection-external`，系统/外部类型仍按其自身规则处理。不要把未来规则写成当前已生效。[^changes][^verify]

## 5. Workshop 发布、分享与行为准则

- Workshop 内容是普通模组目录，`manifest.xml` 放根目录；每个模组必须有 DLL/`IMod`。官方流程用拥有游戏的 Steam 账号和 `steamcmd`，VDF 的 `appid` 示例为 `4348910`；`publishedfileid=0` 创建新条目，保存回填 ID 的 VDF 后可用于更新。`visibility`：0 公开、1 好友、2 隐藏；推荐 `preview.png` 小于 1 MB。游戏内没有上传按钮。[^workshop]
- 因此 Workshop 发布的是 ProbablyEdited **编辑器模组本身**；玩家分享/导入的是编辑器数据目录里的修改 patch 文件，不需要另发独立覆盖模组。patch 只包含修改项可避开整份原文复制；具体 patch schema 和冲突规则由编辑器实现，官方仓库未定义。
- 官方硬规则禁止以任何形式重新分发游戏源代码或游戏资产，明确包含 localization tables；也要求如实说明功能、不得误导玩家、不得恶意/故意破坏性能，并申明实际 capability。分享时应仅含模组作者创建的替换数据和必要 key/locale/table 标识，不打包原始本体文本表。[^conduct]

## 6. 原生开发工具与本轮安全诊断（官方资料复核：2026-11-11）

- `dev.txt` 是开启 F8/F9 的**工具开关**：在 `Probably Stolen.exe` 同目录放空文件，启动时只检查一次；新增或删除后都要重启。启动日志 `[DevTools]` 会报告 enabled/disabled 和检查路径；也可读 `Player.log`（`%USERPROFILE%\AppData\LocalLow\Questing Goose Studio\Probably Stolen\Player.log`）。官方称它不改变存档、模组或游戏行为；demo/playtest 根本不含工具。指南未明确谈成就系统，故不额外推断。[^dev]
- `dev.txt` **不是**批准绕过扫描的开关。另一个独立的 Mods 详情页 **Developer mode** 按本地模组、逐台电脑保存：允许重建后不重新审批，即使检测到未声明 capability 也可启动；但不能越过未列入 `<Assemblies>` 的 DLL，下一次 Activate/Review and enable 仍执行完整规则。它绕过常规版本审批/能力确认，不适合作为正常安全模式验收；禁止用它绕过 scanner rejection。官方文档没有 `mod-dev` 命令，描述的是 UI 按钮；`mod-trust` 只读显示本机 developer mode 与当前信任状态。[^caps][^changes]
- 本模组相关、建议**只读**命令：`mod-scan probably_edited`（也可 `mod-scan <mod-folder-path>`；输出 manifest 声明/扫描检测 capability、发现点、硬拒绝、程序集清单及版本 fingerprint，不放行或修复任何拒绝）；`mod-trust probably_edited`（本机批准哈希、capabilities、developer-mode 状态及会话信任状态）；`mod-trust-list`（远端名单状态）。不要用 `mod-trust-list-fetch`：指南未将其列为只读，且刷新远端状态不服务于本测试。`help`、`man <command>`、`user-commands`、`all-commands` 是帮助/命令发现。[^dev][^caps]
- 日志：F8 控制台呈现 `ModLog`/`Debug.Log`、警告和堆栈；`[ModLoader]` 行始终显示。游戏 info 默认隐藏；F9 **Command > Toggle Verbose Log** 仅开启额外信息日志（会改运行时显示设置，不改业务状态）。F8 控制台里模组自有及加载器日志默认可见。不要执行 `all-commands` 中操作对象/调用方法等引擎命令；它们直接作用于运行中的游戏，官方要求仅在测试存档使用。[^dev]
- 定位/语言检查命令仅按文档支持的窄用途：`loc-plural-test <table> <key>` 测试某本地化条目的数字变体；`loc-smart-list` 列出使用 plural formatting 的条目。官方未记录通用 string-table/key 枚举、当前 UI/预设状态检查器或原生 UI 树检查器；F9 的 Modding Panel 是书籍编辑/重载、纸张 sprite 选择和资源查看器，并非通用 UI 调试器。不要把不存在的 inspector 当验收工具。[^dev]
- 当前 UI/预设删除测试清单：① 保持 normal safety mode，不启用 Developer mode；仅在 parent 明确决定允许临时工具旗标后才创建 `dev.txt`，创建后重启并核对 `[DevTools]` 行，完成后移除并再重启回正常模式。② 可用 `mod-scan probably_edited` 和 `mod-trust probably_edited` 记录安全扫描/批准基线；扫描若拒绝，停下修正模组，不以开发者模式放行。③ 正常 UI 路径删除测试预设，确认目标预设消失、其他预设及当前生效预设保持不变；如需验证持久化，按 UI 正常保存后重启，再确认删除结果与其他预设不变。只用可丢弃的测试预设，不调用 F9 改钱/解锁/生成物品类按钮，也不做 cheat 测试。④ 查看 F8/Player.log 中本模组日志、warning、exception/stack trace；仅需本体 info 时临时启用 Toggle Verbose Log。⑤ 关闭控制台/回到主菜单后按 normal safety mode 再确认行为；启用/禁用/重排模组须重启才生效。指南未提供预设删除专用命令、通用原生 UI 检查器或成就影响结论；因此 UI 行为仍须由 parent 按既有正常流程验收。[^dev][^caps]

### OMP Windows 虚拟桌面限制（2026-11-11）

本机Windows native包18.18.2的标准computer窗口接口先枚举再按ID匹配；已知HWND也不能绕过枚举。游戏位于桌面2时实测DWM cloaked=2，原生Win32仍能找到它，但OMP标准接口返回no window matches。Windows能力中spaces=false；display选择物理显示器，不是Windows虚拟桌面编号。源码：[窗口枚举与捕获](https://github.com/can1357/oh-my-pi/blob/v18.18.2/crates/pi-natives/src/desktop/win32/capture.rs#L126-L157)、[能力声明](https://github.com/can1357/oh-my-pi/blob/v18.18.2/crates/pi-natives/src/desktop/win32/mod.rs#L62-L76)。

在标准接口失败后，经用户授权进行了不激活窗口的有限实验：PrintWindow可读取完整游戏画面；一次WM_MOUSEMOVE加WM_MOUSEWHEEL成功入队，但前后画面的滚动位置不变。没有切换桌面、设前台或移动系统光标；已停止原始输入。结论仅为“后台取图可行，本次后台输入未生效”，不以PostMessage成功推断Unity已处理。

OMP的Windows后台输入同样走窗口消息，没有Unity专用或Raw Input后台路线。显式takeover:false阻止自动前台重试，但不能让忽略窗口消息的应用接受输入；不应通过修改OMP或系统设置绕过该限制。后续原生UI验收需用户亲测、用户允许的前台窗口，或独立运行环境。依据：[OMP官方computer说明](https://github.com/can1357/oh-my-pi/blob/main/docs/computer-use.md)、[Windows消息输入实现](https://github.com/can1357/oh-my-pi/blob/v18.18.2/crates/pi-natives/src/desktop/win32/input.rs#L354-L370)、[Microsoft PostMessage语义](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-postmessagew)。

用户随后把OMP终端也放到桌面2；当用户在桌面1活动时，标准窗口枚举仍找不到游戏。移动终端窗口并没有创建独立输入会话。只读复查游戏根窗口为UnityWndClass且没有原生子窗口，也不存在被遗漏的子控件HWND路线。后来用户将游戏移回桌面1并授权前台验收，原先被阻塞的改名及小窗口两项已完成；跨桌面取图仍不能当作后台操作成功。
